# 不動產地政謄本辨識系統

此資料夾是地政謄本版的獨立開發入口，起點為平行金腦專案的 `index - 地政謄本版.html`，於 2026-09-07 分離。

## 開啟方式

雙擊 `啟動地政謄本版.cmd`，會啟動本機服務並開啟 http://127.0.0.1:8011/ 。保留啟動視窗；結束時在該視窗按 Ctrl+C。

不要直接雙擊 HTML 作為日常入口，圖片列辨識與使用統計需要本機服務。若已有舊版服務，先在原啟動視窗按 Ctrl+C，再啟動新版。

異動索引可能把「異動日期／權利人」存成嵌入圖片。本版以本機 Windows 繁體中文 OCR（圖片文字辨識）讀取這些橫列，再依原頁面座標接回事件；不傳送外部服務。需要啟動器使用的 Python 已安裝 PyMuPDF，以及 Windows 已有 zh-Hant-TW 辨識語言。本機環境已驗證。只支援原始文字 PDF 內的索引圖片列，不支援整頁掃描檔。

同批選取地政謄本與異動索引即可。也可另加金腦異動索引作為補充：同標的、日期、部別、次序、原因、異動別、序號與收件字號相符才合併，權利人衝突會提示停止。沒有新姓名時依同登記次序繼承先前已知姓名，移轉或塗銷後更新；不往未知年代倒填。

## 檔案分工

| 項目 | 用途與關係 |
| --- | --- |
| `index.html` | 後續地政謄本版的主要施工檔，獨立副本。 |
| `local_publish.py` | 獨立本機服務，沿用原服務邏輯；預設只開放本機 8011。 |
| `local_index_ocr.py`、`ocr_index_rows.ps1` | 擷取索引圖片列並呼叫本機 Windows 辨識；完成後清除本次圖片暫存。 |
| `啟動地政謄本版.cmd` | 日常雙擊入口；驗證時可加 `--no-browser`，沿用相同服務但不自動開啟預設瀏覽器。 |
| `js` | 本版獨立的 PDF.js 與 Tailwind 實體檔案，更新不影響金腦版。 |
| `反饋謄本`、`地政版謄本` | 本版範例資料副本，與原專案各自維護，不自動同步。 |
| `runtime/usage_stats.json` | 本版獨立使用統計。 |

2026-09-07 已解除目錄連結並移除指回金腦版的捷徑；兩版可各自搬移與更新，不依賴彼此資料夾。Windows OCR、Python 等本機執行環境仍使用目前電腦已安裝的版本。

只有刻意執行兩版比較測試時，才需在 PowerShell 設定 `$env:GOLD_REGISTRY_ROOT = '金腦版資料夾完整路徑'`；一般啟動與本版測試不需要金腦版。

## 資料與目前範圍

瀏覽器資料庫名稱為 `FmgLandRegistryDatabase`，表格範本使用 `FmgLandRegistryTableTemplates` 與 `FmgLandRegistryActiveTemplate`，與金腦版分開。舊版資料不會自動搬入。

指定兩組 PDF 的異動明細 20 筆 × 8 欄已核對一致，修正與驗收範圍見 [比對結果.md](比對結果.md)。先啟動 8011 本機服務，再以 `D:\node\node.exe tests\compare_transcripts.cjs --verify-source` 重跑實際 PDF 解析、圖片列辨識、歷史繼承及補充索引去重測試；樣本通過不代表所有地政謄本格式皆已涵蓋。

本次未建立排程、部署或切換原專案入口，也未複製原專案的 Git 設定與歷史。

## 離線來源交叉核對

預設啟用「文字優先：異常欄位才用局部 OCR 修正」；完整逐頁交叉核對改為選用，預設不勾選。規則、樣本範圍與驗證見 [欄位辨識規則.md](欄位辨識規則.md)。以下說明選用的完整逐頁核對。PDF.js 原始文字與整頁畫面的 Windows OCR 分開取得，依同一檔案、頁碼、欄位標籤及位置配對。權利人、登記次序、日期、擔保債權總金額及面積列出「一致／待核對／OCR 候選／未能核對」，可展開兩邊原文，連回 PDF 頁碼；來源沒有文字層時不算兩方一致。多個可能對象不強行配對。

核對明細僅存在本次解析畫面，未寫入本機資料庫；重整後須重新解析。核對候選不會自動覆寫解析資料。這是來源欄位核對，尚不代表所有解析欄位或整份文件都已驗證；跨行、印章遮蓋、OCR 誤字或雙方都未定位的欄位仍需原文核對。不勾選時只執行既有解析，完成訊息會標示未交叉核對。網路中斷或 OCR 服務失敗會列為未能核對，不算通過。

`local_pdf_crosscheck.py` 將頁面在本機轉為圖片，透過同一 Windows OCR 引擎獨立讀取畫面；PDF 不會傳送外部服務，處理後清除圖片暫存。文字標籤另處理全形空白、不斷行空白及零寬字元，核對原文仍保留。

啟動既有服務後，使用 `D:\node\node.exe tests\pdf-crosscheck.cjs` 測試欄位空白正規化、差異注入、缺值、跨頁／位置隔離、歧義配對及第 5 份實際 PDF；可加檔名測試 `4.土地建物謄本.pdf` 或 `115BK074006IDXC.pdf`。另執行既有 `tests\compare_transcripts.cjs --verify-source` 回歸解析及權利人歷程。

### 紅色浮水印處理

來源交叉核對現會保留原圖 OCR，另以紅色通道淡化紅色浮水印後再次離線辨識，畫面並列兩者。淡化後才與同頁同位置的文字層相符時標為「一致（淡化後）」；未相符、配對不明確或沒有文字層者不升級為一致，不覆寫原解析資料。此方式針對紅色浮水印，不能保證其他顏色或已遮蔽文字均可恢復。

已使用 `115BE050301IDXE.pdf` 驗證原圖 `096年1` → 淡化後 `096年11月14日`，並在既有 8011 入口驗證實際明細。第 4 份謄本與既有兩版權利人歷程回歸通過；此結果不代表所有來源欄位全部一致。測試指令：`D:\node\node.exe tests\pdf-crosscheck.cjs 115BE050301IDXE.pdf`。Windows OCR 與已安裝 Pillow 均在本機執行，原始 PDF 不變，完成後清除本次 OCR 圖片暫存。
